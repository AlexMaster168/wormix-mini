# Unity / Windows — RIFT Artillery 0.3.1

[Windows ZIP](../dist/RIFT-Artillery-Windows-0.3.1.zip) распаковывается целиком. Запуск — `RIFT-Artillery.exe`. Unity Editor и системная Java для готовой игры не нужны: комплект включает локальный движок и сокращённую среду выполнения.

## Проект

Откройте папку [unity](../unity) в Unity Hub, редактор **6000.0.77f1**. Нужен Windows Build Support / Mono. Для запуска из Editor установите JDK 17 и задайте `JAVA_HOME`. Сцена создаётся скриптом сборки; при запуске стартует `RiftGame`.

Файлы: [клиент](../unity/Assets/Scripts/RiftGame.cs), [интерфейс](../unity/Assets/Scripts/RiftGui.cs), [связь с симуляцией](../unity/Assets/Scripts/BridgeClient.cs), [сборка Windows](../unity/Assets/Editor/BuildWindows.cs).

## Общая логика

Unity отвечает за окно, мышь и клавиатуру, интерфейс, текстуры и AudioSource. `desktop-core` запускает тот же `core`, что включён в Android. Это локальный дочерний процесс со стандартными потоками; сервер и интернет не используются.

Протокол UTF-8: каталог, создание боя, фиксированные шаги, выбор оружия, атаки, инструменты, переключение, сохранение и загрузка. Снимок содержит бойцов, запасы, эффекты, снаряды, устройства, канат, цели гонки и изменённую землю. После разрушения передаётся PNG загрязнённого прямоугольника.

Бинарный файл партии общий, версия v4 с чтением v1/v2/v3. Windows сохраняет `battle.bin` в `Application.persistentDataPath`; настройки, кузница и прогресс используют PlayerPrefs. Автоматического переноса прогресса нет.

## Сборка

```powershell
. .\tools\Prepare-BuildEnvironment.ps1
.\tools\Build-Unity.ps1 -Package
```

Скрипт тестирует и собирает симуляцию, создаёт `rift-sim.jar`, копирует общие атласы и 16 Ogg в Unity, собирает Windows64 и комплектную Java через `jlink`. Плеер — `.tmp/pc031`; архив — `dist/RIFT-Artillery-Windows-0.3.1.zip`.

Доступны `-SkipCoreBuild` и `-UnityEditor <путь>`. Для упаковки уже проверенного плеера без перекомпиляции используется [Package-Windows.ps1](../tools/Package-Windows.ps1). Архив содержит манифест SHA256.

Движок проекта — `Assets/StreamingAssets/Engine`; после изменения `core` пересоберите его. В готовом плеере Java находится в `Engine/runtime`. Кэши `Library`, `Temp`, `Logs`, `UserSettings` и сборки исключены из Git.

## Проверки

91 тест механик — для общего ядра. Шесть тестов протокола проверяют команды, ошибки, сохранения и настоящий процесс с русскими строками при системной Windows-1251. Windows-плеер проходит 178 проверок: ресурсы, 12 карт, выбор 100 предметов, телепорт, полёт и сохранение доски, четыре босса, гонка, воспроизведение 16 треков, переключение и сохранение выбора.

Проверочный запуск: `--rift-smoke --rift-report <полный путь>`. Партии теста находятся в отдельном временном каталоге. Снимки записываются после проверок. Для визуальных кадров нужно видимое игровое окно: скрытое окно на тестовом компьютере возвращает чёрный буфер.

[Результаты](QA-0.3.1.md). Управление — в [README](../README.md).

В 0.3.1 добавлены AudioListener, регулятор громкости и F11 / Alt+Enter. Клавиатурные действия проходят через события IMGUI с поддержкой русских символов; удержание экранных стрелок читается в Update. Во время модального окна нижележащие элементы отключены. Комплектная Java не наследует JAVA_TOOL_OPTIONS, JDK_JAVA_OPTIONS и _JAVA_OPTIONS из среды запуска.
